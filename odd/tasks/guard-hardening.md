# guard-hardening

Objective: close the gaps a read-only security audit found in the dev-factory guards (plugin 0.4.0).
Branch: `fix/guard-hardening`. Delivery: ask-on-risk. Test runner: `node --test plugins/dev-factory/scripts/` (gate: `node scripts/control.mjs verify`).

## Specs

- S1 (U1, fail closed). Both PreToolUse hook commands in `plugins/dev-factory/hooks/hooks.json` block (exit 2) when the guard script throws or cannot be parsed, without relying on `onFailure`.
- S2 (U2, scope). `inScope` treats a case variant of a root and a symlink into a root as in scope. `DEV_FACTORY_ROOTS` adds roots to `~/DEV` and never replaces it (confirmed by the user: "DEV_FACTORY_ROOTS aditivo").
- S3 (U2, trust). `isTrusted` is true only when the project directory is exactly a listed root, compared through symlinks; nested directories are not trusted (confirmed by the user: "trust exacto"). A case variant is not trusted (assumption: under-trusting is the safe failure on case-sensitive volumes).
- S4 (U2, hint). A directory containing a newline is never trusted and `trustHint` does not emit a second line for it.
- S5 (U2, docs). README scope and trust sections and the command rule in agents and the `verify` skill describe S2 and S3.
- S6 (U3, more protected files). `editViolation` also blocks, anywhere: `~/.claude/settings.json`, `~/.claude/settings.local.json`, `~/.gitconfig`, anything under `~/.config/git`, and the shell profiles `~/.zshrc`, `~/.zshenv`, `~/.zprofile`, `~/.bashrc`, `~/.bash_profile`, `~/.profile`. Under the scope roots it also blocks `.claude/settings.json` and `.claude/settings.local.json` of any project.
- S7 (U3, shell writes). New `commandViolation(command, { project, cwd, env })` in `path-guard.mjs` returns a violation when a shell command writes to a path `editViolation` protects. A write is: (a) a redirection target (any `>` form); (b) any argument of `rm`, `rmdir`, `mv`, `tee`, `touch`, `chmod`, `chown`, `chflags`, `truncate`, `unlink`, `mkdir`, `ln`, of `sed` or `perl` with an `-i` flag, the `of=` value of `dd`, or of `git checkout|restore|rm|mv|clean|apply|stash`; (c) the last argument of `cp`, `rsync`, `install`. Before the check each word has quotes and backslashes deleted, a leading `~`, `$HOME` or `${HOME}` expanded, globs expanded with `fs.globSync`, and is resolved against the current directory, which follows `cd <dir>` across segments. Segments split on newline, `;`, `&`, `|`, `(`, `)`, backtick and `$(`. Reading a protected file (`cat`, `ls`, `cp` from it, `node <plugin script>`) is not a violation. This is best effort: interpreters and variables can still write.
- S8 (U3, trust list mention). A command that mentions the trust list (the current `branch-guard.mjs:53` pattern) is blocked unless it is read-only: every segment starts with `cat`, `ls`, `head`, `tail`, `wc`, `stat`, `file`, `grep`, `rg` or `diff`, and the command has no `>`.
- S9 (U3, wiring). `path-guard.mjs bash` is a new entry point registered in `hooks.json` as a second PreToolUse hook on `Bash` (with `|| exit 2`). It applies S7 and S8 with no scope gate of its own. The pattern at `branch-guard.mjs:53` is removed, so `branch-guard.mjs` keeps importing only `scope.mjs` and the copies in `scripts/guard/` keep working.
- S10 (U3, setup skill). In `create-verification-skill`, the steps that write `.githooks/`, `scripts/guard/` and `.claude/settings.json` are given to the human as exact commands instead of run by the agent.
- S11 (U3, docs). README "Trust and protected files" lists the S6 files and describes S7 and S8 and their best-effort limit.
- S12 (U4, git command parsing). `checkCommand` in `branch-guard.mjs`: (a) blocks any abbreviation of the skip-hooks long option (a word starting with `--no-v`); (b) also splits segments on newline, single `&`, `(`, `)` and backtick, still inspecting the first `git` of each segment, so `git commit -m "git push origin main"` on a work branch stays allowed; (c) applies the commit rule to `rebase`, `am` and `reset` too; (d) always blocks `update-ref` and `commit-tree`; (e) blocks `branch -f|-M|-D|--force|--delete` and `checkout -B` / `switch -C` when an operand is a protected branch; (f) blocks `include.path` and `includeIf` anywhere in the command, and a `HOME=`, `PATH=`, `GIT_DIR=`, `GIT_EXEC_PATH=` or `GIT_CONFIG*=` assignment in front of `git` (other `GIT_*` such as `GIT_EDITOR` and `GIT_PAGER` stay allowed).
- S13 (U5, hook templates). The four `templates/githooks/*` stubs take the guard directory from the user-scope entry of `dev-factory@factory-marketplace` in `$HOME/.claude/plugins/installed_plugins.json`, only when its `installPath` is under `$HOME/.claude/plugins/cache/`, ships the needed guard script and has no `.orphaned_at`. Otherwise they fall back to `<repo>/scripts/guard`, and fail (non-zero) when that is missing too. A newer version directory that is not the installed one is never used. Assumption: `$HOME` is still read from the environment (the Claude-layer block in S12f is the mitigation), because the stubs cannot be tested against the real home.
- S14 (U6, Stop gate). `verify-gate.mjs`: (a) with a clean tree, verify is skipped only when `HEAD` equals the commit recorded in `<git dir>/dev-factory-verified`; that file is written after a verify that passes on a clean tree; a dirty tree always verifies; (b) when `stop_hook_active` is set it still runs verify and, if it fails, prints a `systemMessage` saying verify is still failing and exits 0; (c) the verify child has a timeout below the hook timeout and a timeout counts as a failure that blocks (exit 2); (d) the decision is a pure exported `verdict(result)` and the script body runs behind `isMain`.
- S15 (U7, attribution). `attribution-guard.mjs`: (a) the message is cut at the scissors line; (b) lines starting with `#` are no longer skipped; (c) any `<word>-by:` trailer whose value names an AI tool is a violation (names: claude, anthropic, openai, chatgpt, gpt-N, copilot, gemini, cursor, codex, fable, opus, sonnet, haiku, devin, aider, windsurf); (d) "generated|created|written|authored|made|built" + "with|by|using" + an AI name (or `ai`) is a violation; (e) the author and committer idents (`git var GIT_AUTHOR_IDENT`, `GIT_COMMITTER_IDENT`) are rejected by email only: `@anthropic.com`, `@openai.com`, an address containing `copilot` or `[bot]`; a human whose name is Claude is not rejected. `Signed-off-by: Ada <ada@example.com>` and git's own comment lines (for example `#\tmodified:   .claude-plugin/plugin.json`) pass.
- S16 (U8, doctor). In `templates/control.mjs` and the root `scripts/control.mjs`, the `git hooks` check is ok only when `core.hooksPath` is `.githooks` and each of `pre-commit`, `pre-merge-commit`, `pre-push`, `commit-msg` exists there, is executable, and mentions its guard script (`branch-guard.mjs`, or `attribution-guard.mjs` for `commit-msg`). The fix text names the first failing stub. (The installed-versus-source version check from the plan is dropped: it would keep `doctor` red while the plugin is being developed.)
- S17 (docs, parent). README branch-policy and hooks sections describe S12 to S16.
